## Что решаем

Готовый `.ipk`-независимый бинарник для старых MIPSel-роутеров (MT7621 и
родственные платформы) скачивают и передают дальше — часто не глядя, что
«внутри» дистрибуции. Статья отвечает на три вопроса:

1. Чем подтверждается целостность скачанного файла?
2. Какие лицензионные уведомления должны сопровождать бинарник?
3. Что известно о лицензиях компонентов, слинкованных в этот бинарник?

Статья не заменяет README репозитория сборки и не описывает установку на
роутер — для этого есть [`keenetic-auto-setup`](https://github.com/saymer-alt/keenetic-auto-setup).

## Контекст

- Сборка выполняется в GitHub Actions из **точного upstream-тега**
  `MetaCubeX/mihomo` (`git clone --branch v1.19.32`), кросс-компиляция
  `GOOS=linux GOARCH=mipsle GOMIPS=softfloat`.
- Релиз содержит до трёх assets: сам бинарник, sidecar `*.sha256` и
  `*.LICENSE` — копия MIT-лицензии upstream именно с этого тега.
- Go-бинарник статически слинкован: в объектный код входят все транзитивные
  зависимости, и их лицензии становятся обязательными при распространении.
- Состав модулей закреплён `go.mod`/`go.sum` upstream-тега, поэтому список
  зависимостей воспроизводим для каждого релиза.

## Как это работает

**Целостность.** Публикация — конечный автомат с запретом перезаписи
здорового бинарника: состояние релиза классифицируется (`build` /
`checksum` / `complete`), sidecar сверяется байт-в-байт с ожидаемой строкой
`<sha256>  <binary>`, а GitHub-дайджест каждого asset проверяется против
локального содержимого. Повторный запуск публикации на полном релизе —
no-op.

**Лицензия upstream.** Mihomo распространяется по MIT (© 2023 KT). Скрипт
`release_license.py` скачивает `LICENSE` именно с тега, из которого собран
бинарник (`https://raw.githubusercontent.com/MetaCubeX/mihomo/<tag>/LICENSE`),
проверяет содержимое на соответствие MIT-признакам и прикладывает отдельным
asset. Конфликт или подмена — fail-closed.

**Состав зависимостей.** Список модулей, реально вошедших в бинарник, лежит
в его встроенной build-info (`go version -m <binary>`). Для
`mipsel-v1.19.32` это 111 эффективных модулей с учётом `replace`-директив
(например, `google.golang.org/protobuf` заменён на форк
`github.com/metacubex/protobuf-go` — исходники берутся из модуля-замены).
Скрипт `scripts/collect_upstream_licenses.py` того же репозитория скачивает
исходники каждого модуля с module proxy по закреплённой версии и читает
реальные лицензионные файлы — не по именам файлов и не по догадкам.

## Требования

- `gh` CLI, авторизованный с правом чтения релизов; `go` — только для
  самостоятельного воспроизведения списка модулей.
- Никаких прав на роутер или VPS: всё проверяется локально.

## Проверка

Целостность скачанного релиза (номер версии подставьте свой):

```sh
gh release view mipsel-v1.19.32 -R saymer-alt/mihomo-auto-build \
  --json assets -q '.assets[] | "\(.name)  \(.digest)"'
sha256sum mihomo-linux-mipsel-softfloat-v1.19.32
```

Ожидаемо: локальная сумма совпадает с полем `digest` и со строкой в
`*.sha256` (`<64 hex>  <имя файла>`).

Состав зависимостей и версии, вшитые в бинарник:

```sh
go version -m mihomo-linux-mipsel-softfloat-v1.19.32
```

Сводка лицензий для `v1.19.32` — файл
[`THIRD_PARTY_LICENSES-v1.19.32.txt`](https://github.com/saymer-alt/mihomo-auto-build/blob/main/THIRD_PARTY_LICENSES-v1.19.32.txt)
в репозитории сборки; полный набор текстов лицензий (`--full`) генерируется
той же командой и предназначен для передачи получателю бинарника.

## Типичные проблемы

### SHA-256 не сходится

Файл скачан не полностью или подменён. Сверяйте не с текстом на странице, а
с полем `digest` через API (GitHub считает его на своей стороне) и с
sidecar-файлом; оба должны совпасть между собой и с локальной суммой.

### В релизе нет `.sha256` или `.LICENSE`

Исторические релизы (`v1.19.31` и старее) опубликованы до введения этих
assets; полный набор гарантирован только для релизов после 2026-10-10.
Досылать артефакты задним числом владельец может только отдельным
согласованным действием — молчаливая перезапись релизных файлов запрещена
контрактом репозитория.

## Что подтверждено, а что нет

**Confirmed (2026-10-10):**

- SHA-256 скачанного артефакта `mipsel-v1.19.32` совпадает с дайджестом
  релиза (`0af50ded…`), sidecar соответствует формату и содержимому.
- Из build-info бинарника извлечено 111 модулей; `replace`-директивы
  обработаны (протестировано контрактом парсера).
- Лицензии всех 111 модулей определены по реальным файлам upstream;
  неразрешённых нет.
- Повторная публикация на полном релизе не изменяет бинарник и checksum
  (тесты конечного автомата).

**Observed:**

- Распределение лицензий v1.19.32: преобладают BSD-3-Clause, MIT и
  Apache-2.0; присутствуют MPL-2.0, LGPL-2.1/3.0 и компоненты под
  GPL-3.0 / GPL-3.0-or-later (семейство `metacubex/sing*`, `mieru`,
  `randv2` и др.) — итого 19 copyleft-модулей.

**Still research / unknown:**

- Практика передачи полного текста третьих лицензий вместе с бинарником
  для будущих релизов (аттач `THIRD_PARTY_NOTICES-<ver>.txt` к релизу —
  решение владельца, см. PR #12).
- Досылка `.sha256`/`.LICENSE` на релизы старше `v1.19.32`.
