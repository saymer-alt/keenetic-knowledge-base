## Что это

POSIX-sh-скрипт под busybox ash (шебанг `#!/opt/bin/sh`) — функция `service`
для просмотра и управления init-скриптами `/opt/etc/init.d`: список с SNN/KNN-префиксами
и цветовой подсветкой, запуск произвольных действий init-скрипта (start/stop/…),
`enable`/`disable` переименованием `SNNname ↔ KNNname`, `edit` в nano/vi (без аргумента —
редактирует сам скрипт). Заголовок: `Managing services in entware`, автор Pavel P.,
TG `@pnpzx`. Устанавливается как исполняемый `service` в PATH (например `/opt/bin/service`).

## Сверка с текущими конвенциями Entware (первоисточники, 2026-09-24)

- `/opt/etc/init.d` + `SNNname` — подтверждено (`Entware/entware`: пакеты с
  `S02auditd`, `S56dnsmasq` и т.п.); официальный установщик предписывает
  `"/opt/etc/init.d/rc.unslung start"` для старта сервисов.
- Официальный [`rc.unslung`](https://github.com/Entware/rtndev/blob/master/entware-opt/files/rc.unslung)
  (пакет entware-opt): на `start` **и** на `stop/restart/kill` перебирает
  `find /opt/etc/init.d/ -perm '-u+x' -name 'S*'` (stop — в обратном порядке).
  Следствия: (1) исполняемый бит обязателен — не-executable файлы Entware не запускает;
  (2) **K-префиксные файлы rc.unslung не исполняет никогда** — ни при загрузке, ни при
  остановке; (3) `*.sh` сорсится, остальное форкается; симлинки включены.
- Итого: `/opt/etc/init.d`, `SNN` и `rc.unslung` — текущие подтверждённые конвенции;
  пара S/K «boot/kill» — классическая busybox/OpenWrt-практика, **в текущем Entware
  вторая половина (K на shutdown) не реализована**; переименование S↔K как способ
  disable — исторический де-факто хак сообщества, не документированный механизм Entware.

## Static review (не выполнялся)

**High:** не обнаружено (привилегий не повышает, деструктивных неожиданных действий нет —
оперирует на `/opt/etc/init.d` от имени администратора по замыслу).

**Medium:**

1. **`enable` сломан без цветов** (строки 187–193): в цветной ветке есть проверка
   `[ "$getPrefix" = "$toPrefixEn" ] && … && return 0`; в бесцветной (строка 192)
   проверка потеряна — «ALREADY BEEN ADDED» печатается **безусловно** и происходит
   `return 0`, т.е. при `showColors=0` включение disabled-сервиса молча не работает.
2. **Статус start/stop проглатывается**: `_control` пайпит вывод в `sed` и завершается
   `return 0` — неудачный stop/start не виден; success-сообщения печатаются независимо
   от результата.
3. **Порядок enable без отката**: сервис стартуется ещё под K-именем, потом `mv -f`;
   при неудаче mv — сервис запущен, но останется «выключенным» на следующую загрузку
   (несогласованное состояние; rollback нет). Зеркально для disable.
4. **Сопоставление имён неоднозначно**: `$1` подставляется в ERE без экранирования
   (`^[A-Z][0-9]{2}${1}$`) — метасимволы в именах ломают матчинг; при одноимённых
   скриптах с разными префиксами берётся первый по списку.
5. **Восстановление возможно только из K**: префикс K→S — единственная понимаемая
   форма «выключено»; выключение chmod-ом или иными префиксами helper не понимает.
6. **Расхождение с exec-bit конвенцией**: helper показывает и «управляет» любыми
   `[A-Z][0-9]*`, тогда как rc.unslung исполняет только `-perm -u+x` — helper может
   «запускать» то, что Entware никогда не стартует.

**Low:** зависимости от busybox-расширений (`echo -e`, `which`, `local`) — на Entware
работает, POSIX-гарантий нет; glob без совпадений даёт stderr-шум `ls` и пустой список;
цвет уходит в не-TTY вывод; `[ "$x" -gt 1 ]` падает на нечисловом значении; usage-строка
рекламирует только `{edit|disable|enable}`, тогда как произвольные аргументы (start/stop/
restart) молча проходят в init-скрипт; `edit` без аргументов редактирует сам helper ($0)
— неожиданное поведение; sed-паттерн `_control` использует путь без экранирования точек
(практически безвредно).
