# Keenetic NVR Watchdog v2.3 — резервный архив 72 часа на камеру

**Статус: candidate.** Офлайн-тесты BusyBox ash пройдены; 9 октября 2026 первая попытка переключения на реальном KN-1012 завершилась автоматическим откатом при ошибке проверки `stat`/времени изменения файла. Повторный успешный live-test ещё требуется. Основной NVR/регистратор работает независимо.

## Исходное ТЗ (август 2026)

- Три RTSP-канала `101`, `201`, `301`, отдельные папки `cctv/cam101`, `cctv/cam201`, `cctv/cam301`.
- `FFmpeg -c copy` (H.265 без перекодирования), `-segment_time 900` (15 минут, фактический разрез зависит от ключевых кадров), MKV с датой и временем.
- **Главный приоритет — хранить каждый завершённый сегмент не менее 72 часов** от последней записи в него (`mtime`). Очистка раз в час; фактическая глубина хранения примерно 72–73 часа. Текущий открытый сегмент не удалять.
- Не ограничивать общий объём NVR и **не удалять файлы моложе 72 часов** ради освобождения места.
- Контролировать заполнение диска: `WARN` при 75%, `CRITICAL` при 90%. Это сигналы для диагностики, **не триггеры очистки**.
- Каждые пять минут проверять существование FFmpeg и актуальность записываемого файла по каждой камере. Перезапускать только неисправную камеру, с ограничением частоты повторов.
- Не терять ошибки FFmpeg: событийный лог и отдельные логи каждой камеры.
- Все секреты RTSP хранятся только локально на роутере (`/opt/etc/nvr-v2.conf`, `chmod 600`), в репозитории — только пример.

**Что означает «не менее 72 часов»:** созданный видеофайл не удаляется раньше времени; это не гарантия, что в архиве будут все 72 часа видео при отключённой камере. Если объёма накопителя не хватит на реальную запись 72 часов, одновременно выполнить обе задачи физически невозможно. Система не пожертвует свежим архивом ради порога заполнения, но запись при полном диске может остановиться.

## Установка прямо с GitHub — без скачивания архива на ПК

Команды рассчитаны на уже диагностированный роутер `192.168.1.2` с Entware, `/opt/bin/ffmpeg`, установленным `cron` и USB-разделом EXT4.

**Шаг 0. Установить необходимые пакеты Entware (один раз):**

```sh
opkg update
opkg install curl coreutils-stat
```

Для загрузки установщика нужен `curl`, для надёжной проверки возраста и размера записанных MKV нужен GNU `stat` из `coreutils-stat`. Оба пакета отдельно проверяются перед переключением; `preflight` больше не пропустит отсутствие `stat`.

**Шаг 1. Только проверка**, ничего не останавливает:

```sh
curl -fSsL https://raw.githubusercontent.com/saymer-alt/keenetic-knowledge-base/nvr/watchdog-v2-candidate/NVR/v2/bootstrap.sh -o /tmp/nvr-install.sh && sh /tmp/nvr-install.sh preflight
```

**Шаг 2. После сообщения `Preflight PASS` — переключение**, резервная запись ненадолго остановится (основной регистратор не затрагивается):

```sh
sh /tmp/nvr-install.sh switch
```

Установщик самостоятельно:
1. Сохранит старый `S99cctv`, `record_cctv.sh`, `cleanup_cctv.sh`, оба crontab в `/opt/etc/nvr-v2-backup`.
2. Извлечёт RTSP-параметры **на роутере**, не отправляя их на GitHub, в закрытый конфиг.
3. Удалит старые NVR cron-задания и остановит старую запись.
4. Запустит отдельный FFmpeg для каждой камеры и проверит свежие MKV.
5. Добавит в рабочий root crontab `*/5 ... check` и `0 * ... cleanup`.
6. При ошибке переключения попытается автоматически восстановить старую схему.

**Шаг 3. Диагностика:**

```sh
sh /opt/etc/nvr-v2.sh status
crontab -l
tail -n 30 /tmp/mnt/f9bf834b-5650-d901-f0aa-834b5650d901/cctv/.nvr-v2/events.log
```

Проверь свежесть MKV всех трёх камер, следующий пятиминутный запуск и работоспособность после перезагрузки. При подключённом диске лог событий сохраняется в `cctv/.nvr-v2/events.log`. Логи камер могут содержать RTSP URL, **не публикуй их без скрытия паролей**.

**Откат:**

```sh
sh /opt/etc/nvr-v2-backup/rollback.sh rollback
```

После **автоматического отката** `switch` теперь можно запустить снова после успешного `preflight`: установщик сохраняет и повторно использует исходный `/opt/etc/nvr-v2-backup`, ничего поверх него не пишет. Если резервная копия повреждена или неполная — переключение блокируется. Не удаляйте каталог резервной копии перед повторным запуском.

## Технические оговорки

- В FFmpeg 6.1.4 опция RTSP `-timeout` заменяет старую `-stimeout`. Предварительная проверка требует её поддержки.
- Утилита `stat -c %Y/-c %s` обязательна для проверки свежести файлов. Без неё прежний status ошибочно показывал возраст файла равным Unix-времени; теперь `preflight` блокирует переключение, а `status` выводит `stat_error` вместо гигантского числа.
- Установщик даёт камерам до 60 секунд на появление первого корректного MKV; при сбое инициируется автоматический откат, без изменения регистраторов за пределами этого роутера.
- Файлы удаляются по `mtime` (время последней записи), а не по времени в имени. Это не сокращает требуемые 72 часа даже для сегментов, завершившихся позже номинального времени.
- Проверка здоровья оценивает **возраст последней записи**, а не только наличие PID, и учитывает время запуска нового процесса (startup grace). Очень длинный открытый сегмент может временно сохраняться дольше 72 часов.
- Запущенный FFmpeg может содержать пароль RTSP в `/proc/<pid>/cmdline`; вывод `ps w` не публиковать.
- Офлайн-тесты не заменяют проверку на самом Keenetic. До завершения испытаний `main` содержит старую инструкцию, v2.3 находится в отдельной ветке.

## Защита RTSP-пароля при переходе с v1 на v2.3

**Пароль камеры не нужно вводить в терминале и нельзя записывать в GitHub.**
При `switch` установщик читает строки `RTSP_USER`, `RTSP_PASS`, `RTSP_IP`
из существующего `cctv/record_cctv.sh` **только на самом Keenetic**.
Они записываются в **`/opt/etc/nvr-v2.conf` с правами `600`**.
Конфиг находится за пределами репозитория, и скачивание через GitHub передаёт
только публичный код. `NVR/v2/nvr.conf.example` содержит исключительно заглушки.

После установки можно проверить только права, **не раскрывая содержимое**:

```sh
ls -l /opt/etc/nvr-v2.conf
ls -ld /opt/etc/nvr-v2-backup
```

Старый `record_cctv.sh` и его локальная резервная копия продолжают содержать
секрет до его замены. **Нельзя загружать в GitHub ни эти файлы, ни локальный
`nvr-v2.conf`, ни полный вывод `ps`/логи FFmpeg с RTSP URL.**
Учитывая, что первоначальный пароль уже появлялся в переписке и истории SSH,
желательно сменить его в камере/регистраторе после миграции и обновить только
локальный файл `/opt/etc/nvr-v2.conf`.

Для дополнительной страховки в `NVR/v2/.gitignore` перечислены файлы
локальных секретов и записи, однако **`.gitignore` не заменяет проверку
содержимого перед каждым коммитом** и не очищает историю от случайных утечек.
