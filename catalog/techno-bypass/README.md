# Каталог TechnoBypass

Структурированный навигационный слой по экспорту Telegram-канала
**TechnoBypass** — личного канала владельца этого репозитория
(16.09.2025 — 18.09.2026, 1161 сообщение).

> ⚠️ **Канал — исследовательский источник, а не проверенная документация.**
> Появление ссылки или утверждения в канале означает только то, что оно было
> опубликовано. Форварды — свидетельство публикации, а не технической
> истинности. Проверенные факты живут в canonical-статьях этого репозитория
> и в коде проектов-владельцев поведения (см. `AGENTS.md` корня).

Исходный экспорт HTML в репозиторий **не коммитится** (сырьё может содержать
приватные ссылки и учётные данные). Provenance-якорь каждой записи каталога —
идентификатор сообщения Telegram (`#1234`) и дата; при наличии свежего экспорта
сообщение находится по id за секунды.

## Статусы записей

Каталог отделяет индексирование от проверки. Статус записи:

- **Source** — факт появления в TechnoBypass (дата, id сообщения);
- **Research** — потенциально полезно, требует проверки;
- **Observed** — в канале зафиксирован реальный тест/наблюдение автора или
  цитируемого автора;
- **Confirmed** — подтверждено текущим кодом/документацией (в этом каталоге
  почти не используется — подтверждение фиксируется в статьях, не в индексе);
- **Historical** — привязано к старым версиям/условиям;
- **Obsolete/Superseded** — известна замена;
- **Dead** — ссылка известна как неработающая;
- **Unclassified** — требует разбора.

Уверенный тон поста ≠ `Confirmed`. Форвард чужого утверждения = **Source** для
утверждения «это было опубликовано», обычно **Research** для технической сути.

## Конвейер

```text
TechnoBypass (экспорт Telegram, вне git)
        ↓  tools/parse_telegram_export.py (детерминированный парсер)
dataset (messages/links/stats, вне git — содержит сырьё)
        ↓  ручная куризация
этот каталог (Source/Research/Observed + provenance)
        ↓  проверка по коду/документации
canonical-статьи репозитория
        ↓  перенос в проект, владеющий поведением
```

## Повторный запуск на новом экспорте

```sh
python3 tools/parse_telegram_export.py --out <рабочий_каталог_вне_git> messages*.html
```

Парсер только читает экспорт и пишет JSON/статистику в указанный каталог; файлы
каталога он не трогает — описания и статусы курируются вручную, поэтому
повторный запуск ничего не перезаписывает. Выход содержит сырой текст канала —
не коммитить.
