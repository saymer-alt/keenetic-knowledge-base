# REVIEW — независимый аудит каталога TechnoBypass (TASK-TB-02A)

Дата: 2026-09-19. Аудит выполнен по свежему прогону парсера на том же
экспорте, с проверкой утверждений каталога против исходного dataset
(сообщения/ссылки), а не по памяти о его создании.

Контекст публикации: каталог в момент аудита существует **только локально**
(коммиты `8c1f4a5`/`5e91638`/`9b5ecac`); push заблокирован расхождением с
`origin/main` (см. отчёт TASK-TB-01P) — оператор параллельно опубликовал свою
документационную интеграцию (README/AGENTS/ROADMAP). Аудит от этого не
зависит; выводы применимы к любой из сторон reconciliation.

## Сильные стороны

- **Provenance-дисциплина**: все 543 уникальных id сообщений, на которые
  ссылается каталог, существуют в корпусе; даты при id сверены программно —
  расхождений нет. Выборочная семантическая проверка 31 утверждения из всех
  13 тем: 30/31 подтверждены текстом сообщения; 1 «провал» — ложный
  (строка в имени PDF-вложения `#815`, а не в тексте).
- **Статусная модель соблюдена**: единственное употребление `Confirmed` —
  легенда статусов в README каталога; все 4 употребления `Observed`
  опираются на явные формулировки теста в источнике («сам проверил», «у
  меня на роутере», «работает на четырёх моих серверах», «отлично
  работает» — #96, #59, #1089, #1083), проверено по тексту сообщений.
  `Historical`/`Superseded` использованы точечно (ручные бюллетени
  bypass_wa, гайд ручного обновления Mihomo, warpscout-фаза генератора).
- **Чувствительное не протекло**: повторный скан шаблонов (приватные
  t.me-ссылки, tg://proxy-секреты, vless://-конфиги, PSK, private key)
  по всем 22 MD-файлам — чисто.
- Навигация: все относительные ссылки разрешаются; из README каталога любая
  тема доступна в 1 клик, из README репозитория — в 2.

## Структурные проблемы

1. **Расхождение чисел проектов** (исправлено в этом аудите): заголовки
   утверждали «206 проектов» при 205 строках таблицы. Причина: 206 — число
   уникальных URL типа github-repo, а не проектов; группировка owner/repo
   даёт меньше. После исправления (см. «Дубликаты») каноническое число —
   **204**.
2. **INVENTORY.md не знает о новых разделах**: в его таблицах нет
   `catalog/` и `tools/` (появились после его написания). Нужно добавить
   строки при следующем проходе (вне scope этого аудита — правка INVENTORY
   не входит в «малые исправления»).
3. **Каталог не синхронизирован с новой документацией оператора**:
   удалённый `ROADMAP.md` (Phase 2) описывает построение этого каталога как
   будущую работу, удалённые README/AGENTS §3 не ссылаются на
   `catalog/techno-bypass/`. После reconciliation нужен короткий doc-sync
   (отметить выполненное, поставить ссылки).
4. Мелкие шероховатости формулировок, исправленные здесь: утверждение о
   `forum.keenetic.com` (в корпусе только `forum.keenetic.ru`, 9 вхождений);
   происхождение check-host.net «#1024+» заменено на фактические id.

## Provenance-замечания

- `#1668` (dpi-zapret.md) и `#5332` (xray-vless.md) — это номера
  GitHub discussion/issue, не Telegram-сообщений; из контекста это видно,
  но при машинном парсинге `#NNNN` они неотличимы. Оставлено как есть;
  конвенция: «issue #N» / «discussion #N» = GitHub, «#N» отдельно =
  сообщение канала.
- Форварды корректно атрибутированы («форвард X», «Observed автором
  форварда»), нигде не выданы за наблюдения владельца.
- Сводные «мини-каталоги» самого канала (#1022–#1028) использованы как
  первоисточники-якоря — корректно, они и есть сообщения канала.

## Дубликаты (найдено и исправлено)

- `github.com/bol-van/zapret` vs `github.com/bol-van/zapret.git` —
  тривиальный URL-вариант, вёл к лишней строке таблицы и расхождению
  счётчиков. Исправлено: в парсер добавлено срезание `.git`-суффикса для
  git-хостов (повторный прогон: 1633→1632 уникальных URL, 1094→1093
  реальных), таблица перегенерирована, строки объединены (zapret:
  occ=7, messages 354–1026).
- Фorks НЕ склеивались с upstream (проверено: `gennadykataev/awg-easy`,
  `LarinIvan/MagiTrickle_Mod`, семейство tg-ws-proxy — отдельные записи);
  issue/release/blob не схлопнуты с корнем репозитория (подтипы в
  links.json различаются). Нерелевантных «похожих имён» в группировке нет —
  группировка по owner/repo структурно исключает склейку чужих репозиториев.
